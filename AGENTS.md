# Architecture Pro Max repository instructions

This repository maintains a portable architecture-reasoning Agent Skill.

## Source of truth

- `skills/architecture-pro-max/` is canonical.
- `adapters/` is generated by `tools/generate_adapters.py`; never hand-edit generated files.
- Keep `SKILL.md` operational and concise. Put deep explanations in `references/` and structured facts in `data/`.
- Platform wrappers may adapt discovery/activation syntax but must not change architecture policy.

## Change protocol

For a behavior change:
1. update the canonical skill/reference/data first;
2. update tests;
3. run `python skills/architecture-pro-max/scripts/validate.py`;
4. run `python tools/generate_adapters.py`;
5. run `python -m unittest discover -s tests -v`;
6. update README/docs/changelog when user-visible behavior changes.

## Quality rules

- Do not hard-code a preferred architecture or framework as globally optimal.
- Recommendations must be based on explicit constraints and quality attributes.
- Always include a simpler viable alternative and migration thresholds.
- Never require an agent to reveal hidden chain-of-thought; require concise rationale, assumptions, matrices and risk review instead.
- Avoid duplicating the same long guidance in multiple always-on files.
- Scripts must use Python standard library only unless a future ADR explicitly changes this rule.
- Installer must be idempotent and must not delete unrelated user files.
